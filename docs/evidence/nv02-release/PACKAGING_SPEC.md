# NV02 Release Packaging Specification

This document describes the **source‑only** packaging process for the `apps/chrome-controller` component.

## Overview
The `build-packager.mjs` script creates a deterministic `tar.gz` archive that contains **only the source files** of the Chrome‑Controller.  Alongside the archive a **manifest** (`source-manifest.json`) is generated.  The manifest lists every file shipped in the archive together with a SHA‑256 hash, the package name and version.

## Manifest Schema
The manifest must conform to `manifest-schema.json`:

{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "title": "Chrome‑Controller Source Manifest",
  "type": "object",
  "required": ["name", "version", "files"],
  "properties": {
    "name": { "type": "string" },
    "version": { "type": "string" },
    "files": {
      "type": "array",
      "items": {
        "type": "object",
        "required": ["path", "sha256"],
        "properties": {
          "path": { "type": "string" },
          "sha256": { "type": "string", "pattern": "^[a-f0-9]{64}$" }
        }
      }
    }
  }
}


## Deterministic Archive
* Files are added in **lexicographic order**.
* The archive is created with `tar`'s `portable` flag, which normalises UID/GID, file mode and timestamps (all set to zero).  This guarantees that repeated builds produce byte‑identical archives when the source tree is unchanged.

## Verification Steps (executed by the script)
1. **Generate manifest** – compute SHA‑256 for every file under `apps/chrome-controller`.
2. **Validate manifest** – the manifest is checked against the JSON schema using **Ajv**.
3. **Hash verification** – each file’s computed hash is compared to the entry in the manifest; any mismatch aborts the build.
4. **Create archive** – a deterministic `tar.gz` is written to the path supplied on the command line (default `chrome-controller-src.tar.gz`).

## Test Suite
`tests/nv02-release-package.test.mjs` provides three deterministic tests:
1. **Archive existence** – ensures the archive file is created and non‑empty.
2. **Manifest validity** – validates the manifest against the schema and re‑computes each file’s hash.
3. **Archive contents** – extracts the archive to a temporary directory and asserts that the extracted file list exactly matches the manifest’s file list.

All tests are designed to be **repeatable** and must pass on any clean checkout of the repository.

## Usage
bash
node scripts/nv02-release/build-packager.mjs [output‑archive.tar.gz]

If no argument is supplied the default archive name `chrome-controller-src.tar.gz` is used.
